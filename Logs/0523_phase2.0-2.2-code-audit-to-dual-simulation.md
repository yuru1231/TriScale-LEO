### 已知設計限制（不影響 Phase 2.0 驗證）

在 `mode=grid` 中，beam centers 是用 `GetHexBeamCenters()` 計算後再經 `EcefOffsetToEnu()` 轉到 ENU frame。  
`GetHexBeamCenters()` 假設 satellite nadir = footprint center（即 elevation = 90°），因此：

- **elevation ≈ 90°（衛星正上方）**：beam center ENU 位置正確 
- **低仰角時**：beam center 相對於 ROI 的位置會有偏差，beam gain 可能不準確

**Phase 2.0 驗證條件**：center cell SNR ≈ Phase 1.1 beam 9 < 0.5 dB，屬於 elevation ≈ 90° 情境，此限制不影響 Pass/Fail 判斷。

Phase 2.1 以後若需要更精確的低仰角 beam gain，需引入動態 beam center 計算（以當前衛星 ENU 位置為基準）。

---


## 新增函式

### `read_all_tles(filename: str) -> list`

從多衛星 TLE 檔案讀取所有 3-line 群組。

- 跳過 `#` 開頭與空白行
- 偵測 TLE group 邊界（`line.startswith('1 ')` / `'2 '`）
- 回傳 `list[(ephem.EarthSatellite, name_str)]`

---

### `scan_passes(sat, ..., min_visible_elev_deg=0.0) -> list`

以 `scan_step_s` 掃描單顆衛星在 `[0, search_window_s]` 的仰角，用狀態機偵測 pass entry/exit。

```
in_pass 狀態機：
  False → 仰角 ≥ 門檻 → True (記錄 t_enter, 開始追蹤 peak)
  True  → 仰角 < 門檻 → False (記錄 t_exit, 儲存 pass dict)
  視窗末端仍在 pass → 強制關閉
```

回傳 `list[{t_enter_s, t_peak_s, t_exit_s, peak_elev_deg}]`

---

### `find_qualifying_passes(all_sats, ..., min_peak_elev_deg) -> list`

對所有衛星呼叫 `scan_passes`，篩選 `peak_elev_deg >= min_peak_elev_deg` 的 pass，按 `t_peak_s` 排序。

- 含進度列印（`idx/total`）
- 回傳含 `sat`, `name` 欄位的 pass list

---

### `propagate_window(sat, ..., t_abs_start_s, t_abs_end_s, step_ms, start_utc) -> list`

在絕對時間視窗 `[t_abs_start_s, t_abs_end_s]` 傳播衛星。

**keypoint**：`time_s` 欄位為 **0-based**（= `i × step_s`），而非絕對時間。
兩顆衛星使用相同視窗，因此兩份 CSV 的 `time_s` 對齊，Phase 2.2 C++ 迴圈可以索引同步。

---

### `write_csv` 更新

接受 `argparse.Namespace`或 `dict`（sequence mode）作為 metadata。

sequence mode 新增 comment 欄位：
```
# window_start_s : ...
# window_end_s   : ...
```

---

## Sequence Mode 流程

```
1. read_all_tles()         ← 讀 66 顆 Iridium 衛星
2. find_qualifying_passes() ← 掃描 7200s，找 peak ≥ 50° 的 pass
3. 印出排序後的 qualifying pass list
4. 選取 pair_index 與 pair_index+1
5. 計算 combined window:
     win_start = min(enter_i, enter_i1) - margin_s
     win_end   = max(exit_i,  exit_i1)  + margin_s
6. propagate_window() × 2   ← 兩顆衛星，相同視窗
7. write_csv() × 2          ← 0-based time_s 對齊
8. 輸出 sequence_summary.json
```

## 新增內容（anonymous namespace）

### `DualCellStats` struct

每個 ROI 格點（全部 d×d 個）的統計累積：

```
sat[i]   : coverageSI, sumSnrSI, maxSnrSI, nSamplesSI
sat[i+1] : coverageSI1, sumSnrSI1, maxSnrSI1, nSamplesSI1
Greedy   : sumGreedySnr, nGreedy  （每步取兩顆中 SNR 較高者）
```

### `DualSimState` struct

包含 `orbitI`、`orbitI1`（兩份 orbit 向量）、`idxI`/`idxI1`（各自的指標推進器）、Phase 2.3 的 `thresholdsPct`/`overlapTimesS`/`nInFootprint`/`snrThreshDb`。

### `AppendDualCellCsvRows()`

每步寫入 in-footprint 格點的雙衛星結果：

```
time_s, row, col, cx_m, cy_m,
elev_i_deg, snr_i_dB, sinr_i_dB,
elev_i1_deg, snr_i1_dB, sinr_i1_dB,
best_sat
```

`best_sat` 規則：
- `0` → sat[i] SNR 較高（或 sat[i+1] 不可見）
- `1` → sat[i+1] SNR 較高（或 sat[i] 不可見）
- `-1` → 兩者均不可見（此步不寫入）

衛星不可見時對應欄位填入 `-999.0`（sentinel）。

### `WriteDualSummaryCsv()`

整段模擬結束後，對全部 d×d 格點輸出摘要：

```
row, col, cx_m, cy_m, in_footprint,
coverage_i_s, mean_snr_i_dB, max_snr_i_dB,
coverage_i1_s, mean_snr_i1_dB, max_snr_i1_dB,
greedy_mean_snr_dB
```

`greedy_mean_snr_dB` = Phase 2.4 Greedy 分配策略的基準 SNR。

### `WriteDualOverlapJson()`

Phase 2.3 重疊閾值偵測結果：

```json
{
  "n_in_footprint": 17,
  "snr_threshold_dB": 0.0,
  "thresholds_pct": [10, 25, 50, 75, 90],
  "sat_i1_coverage_times_s": {
    "10pct": t10,
    "25pct": t25,
    "50pct": t50,
    "75pct": t75,
    "90pct": t90
  }
}
```

`-1.0` 表示該閾值在視窗內未達到。同時在 console 印出摘要表。

### `DualUpdateStep()` callback

每步（updateMs）執行：

```
1. 推進 idxI / idxI1 指標（找最後一個 timeS <= t 的軌道點）
2. 讀取 elevI, elevI1
3. visI  = (elevI  >= minElevDeg)  → ComputeFrameResults for sat[i]
4. visI1 = (elevI1 >= minElevDeg) → ComputeFrameResults for sat[i+1]
5. AppendDualCellCsvRows（至少一顆可見時才寫入）
6. 累積 DualCellStats（coverageS, sumSnr, maxSnr, greedy）
7. 計算 cellsI1Covered（sat[i+1] SNR >= snrThreshDb 的格點數）
8. 對尚未觸發的閾值，判斷是否首次達到
9. Reschedule 直到 max(orbitI 末端, orbitI1 末端)
```
