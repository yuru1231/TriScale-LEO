# 2026/05/27

## Phase 2.5 — Low-Elevation UPA Beam Correction

## 目標：
修正 Phase 2.0/2.2 中 UPA beam gain 在低仰角的系統誤差。

---

## 問題

### 發現

在 **Phase 2.0 code audit** 中註記

- 低仰角時 beam gain 可能不準確
- 重新檢視`BuildArrayTransform` 時發現 `satPos.y`只被當作 y 軸 offset 傳入，**未做任何旋轉角計算**
- arc mode 的設計前提 `satPos.y = 0` 在 Iridium 86.4° 傾角的 SGP4 真實軌道下不成立

Validation 數值（修正量 < 0.25 dB、中心格 Δ = 0.000）也印證此問題在數據層面不易直接觀測。

> 透過grill me skill 協助審查

---

### 原始設計（arc mode）
`BuildArrayTransform()` 在 Python `get_angles_to_satellite()` 中被設計用於 arc mode：
- 衛星只在 x-z 平面上移動（`satPos.y = 0` 恆成立）
- y 軸旋轉能正確對齊衛星方向
- `tanVecZ = -satX / (satZ + rEarth)` 正確計算旋轉角

### Grid / Dual mode 的問題（Phase 2.0/2.2）
使用 SGP4 真實軌道後，衛星有任意方位角：

```
ENU 座標系下（Tokyo ROI 中心為原點）：
  satPos.x = East  分量（衛星在觀測點的東方偏移）
  satPos.y = North 分量（衛星在觀測點的北方偏移）
  satPos.z = Up    分量（對應仰角高度）
```

- `satPos.x` = East 分量
- `satPos.y` = North 分量（Iridium 傾角 86.4°，Tokyo ROI 過境大部分時間 satPos.y ≠ 0）

**旋轉缺陷**：原始 `BuildArrayTransform` 只用 `satPos.x` 計算 y 軸旋轉角，`satPos.y` 被丟棄：

```
原始邏輯（僅 y 軸旋轉）：
  satHoriz = satPos.x          ← 錯誤：把水平距離當成純 East 分量
  tanVecZ  = -satX / (satZ + rEarth)  ← 僅考慮 E 方向衛星

  at.satY = satPos.y - spacing/2   ← North 分量塞入 UPA y 軸，
                                      但 UPA 框架未旋轉，方向對不上
```

- UPA array 是矩形（`nBeamsX=5, nBeamsY=4`），**x 方向和 y 方向 beam pattern 不同**
- 衛星若從 SE 方向進入 Tokyo ROI，UPA x/y 方向的 beam gain 被混淆

### 旋轉問題:為何需要 z 軸預旋轉

```
俯視圖（ENU x-y 平面，z 軸朝上）：

正確狀態（Phase 2.5 修正後）：
  N
  ^
  |
  |   衛星 S（SE 方向）
  |    /
  |   /  satPos.y < 0, satPos.x > 0
  +--/-----------> E
     
  Step 0 z 旋轉：把 S 的水平投影轉到 +x 軸
  → UPA array 正面對準衛星水平方向
  → beam gain 計算正確

錯誤狀態（Phase 2.2 原始）：
  N
  ^
  |
  |   衛星 S（SE 方向）
  |    /
  |   /  satPos.y 被忽略
  +--/-----------> E
     ↑
  UPA 的 "x" 方向被當成水平距離
  但 UPA "y" 方向（North）未旋轉對齊
  → 使用 5-beam x 方向 pattern 計算 SE 方向衛星 → 錯誤 gain
```

### 影響估計

Iridium-75 45 在 Tokyo（Peak 66.4°，t=50s，entry t=0s）：
- t=0s：衛星從 SE 方向進入，`satPos.x > 0, satPos.y < 0`，方位角誤差顯著
- t=50s：衛星近頭頂，`satPos.y → 0`，誤差最小（peak SNR 最準確）
- t=440s：衛星出境向 NW，`satPos.x < 0, satPos.y > 0`，誤差再度顯著

## 數學模型（Phase 2.5 旋轉推導）

### 座標系定義

以 Tokyo ROI 中心為原點，採用 ENU（East-North-Up）右手座標系：

```
x̂ = East
ŷ = North
ẑ = Up
```

衛星位置向量（地心慣性系轉換後）：

```
s = (E_s, N_s, U_s)   [m]
```

UPA 陣列位於 z=0 平面，陣列法向量初始指向 +z（Up），陣列 x 軸對齊 East。

---

### Step 0：z 軸預旋轉（Phase 2.5 新增）

**目的**：將衛星水平投影對齊 +x 軸，使 UPA 平面只需做後續的仰角（y 軸）旋轉。

衛星水平距離：

```
d_h = sqrt(E_s² + N_s²)   [m]
```

z 軸旋轉角 φ（從 +x 轉向衛星水平方向的角）：

```
cos φ = E_s / d_h
sin φ = N_s / d_h
```

z 軸旋轉矩陣（右手定則，沿 -z 旋轉）：

```
      ┌  cos φ   sin φ   0 ┐
R_z = │ -sin φ   cos φ   0 │
      └    0       0     1 ┘
```

旋轉後衛星座標（映射到 x-z 平面）：

```
s' = R_z · s = (d_h, 0, U_s)
```

驗證：旋轉後 s'.y = 0，衛星水平分量完全落在 +x 軸，N 分量歸零。

**退化條件**（向後相容）：

```
若 d_h < 1 m（衛星正頭頂）：φ = 0，R_z = I（Identity），行為不變
若 N_s = 0（arc mode 或純 E-W 軌道）：sin φ = 0，R_z = I，行為不變
```

---

### Step 1：Array Corner Shift（修改後）

Phase 2.2 錯誤地使用 `E_s` 作為水平距離，Phase 2.5 改為 `d_h`：

```
    ┌ at.satX ┐   ┌ d_h  − (N_x · N_bx / 2) · Δ ┐
    │ at.satY │ = │  0   − (N_y · N_by / 2) · Δ │
    └ at.satZ ┘   └             U_s              ┘
```

其中：
- `N_x, N_y` = 波束格狀數（Beam grid count）
- `N_bx, N_by` = 每波束天線數（Antenna per beam）
- `Δ` = 天線間距（antenna spacing，= λ/2）
- `(N_x · N_bx / 2) · Δ` = 陣列半寬，使陣列中心對準衛星

---

### Step 2：y 軸旋轉（仰角對齊，既有邏輯）

**目的**：將 UPA 法向量從 +z 旋轉至指向衛星（z 旋轉後，衛星在 x-z 平面）。

仰角旋轉角 θ：

```
tan θ = −at.satX / (U_s + r_E)

cos θ = (U_s + r_E) / sqrt(at.satX² + (U_s + r_E)²)
sin θ = −at.satX   / sqrt(at.satX² + (U_s + r_E)²)
```

其中 `r_E = 6371000 m`（地球半徑，用於近似大圓距離）。

y 軸旋轉矩陣（繞 ŷ 軸）：

```
      ┌ cos θ   0   sin θ ┐
R_y = │   0     1     0   │
      └ -sin θ  0   cos θ ┘
```

---

### 複合旋轉

對任意天線單元位置向量 **p** = (p_x, p_y, p_z)，Phase 2.5 的完整座標變換為：

```
Step 0 (z-rotate):    p'  = R_z · p
Step 1 (y-rotate):    p'' = R_y · (p' + at_offset)
```

展開 z 旋轉：

```
p'_x =  cos φ · p_x + sin φ · p_y
p'_y = -sin φ · p_x + cos φ · p_y
p'_z =  p_z
```

加上 corner shift 後做 y 旋轉：

```
q_x = p'_x + at.satX
q_y = p'_y + at.satY
q_z = p'_z + at.satZ

p''_x =  cos θ · q_x + sin θ · q_z
p''_y =  q_y
p''_z = -sin θ · q_x + cos θ · q_z
```

---

### Step 3：空間頻率計算（GetSpatialFreqs）

對 z 旋轉後的座標 `p'` 計算空間頻率：

```
u_x = p''_x / λ · 2π     [rad]
u_y = p''_y / λ · 2π     [rad]
```

其中 λ = c / f_c（載波波長）。

Beam gain 為所有天線單元的相位加總（Array Factor）：

```
AF(u_x, u_y) = Σ_{m,n} exp(j · (m · u_x + n · u_y))
```

### Phase 2.2 vs Phase 2.5 的旋轉差異

| | Phase 2.2 | Phase 2.5 |
|---|---|---|
| 水平距離 | `E_s`（丟棄 N_s） | `sqrt(E_s² + N_s²)` |
| z 軸預旋轉 | 無 | `R_z(φ)` |
| y 軸旋轉基準 | 錯誤的水平距離 | 正確的 `d_h` |
| 適用情境 | arc mode（N_s=0） | 任意軌道方位角 |
| 誤差來源 | UPA x/y 方向混淆 | 無（已修正） |

## 修改內容

### `ArrayTransform` struct — 新增 `cosZ, sinZ`

```cpp
struct ArrayTransform {
    double satX, satY, satZ;  // 衛星位置（z 旋轉後，已在 x-z 平面）
    double cosR, sinR;        // y 軸旋轉（既有）
    double cosZ, sinZ;        // Phase 2.5: z 軸預旋轉
};
```

### `BuildArrayTransform` — 新增 Step 0（z 預旋轉）

```
Step 0 (NEW): z-旋轉對齊
  satHoriz = sqrt(E_s² + N_s²)
  cosZ = E_s / satHoriz,  sinZ = N_s / satHoriz
  → 衛星水平方向映射到 +x 軸

Step 1 (修改): array corner shift 使用 satHoriz（非 satPos.x）
  satX = satHoriz - (Nx·Nbx/2)·spacing
  satY = 0        - (Ny·Nby/2)·spacing

Step 2-4 (不變): y 軸旋轉計算
```

### `GetSpatialFreqs` — 新增 Step 0（z 旋轉應用）

```
Step 0 (NEW): 對 pos 套用 z 旋轉
  posXr =  cosZ·pos.x + sinZ·pos.y
  posYr = -sinZ·pos.x + cosZ·pos.y
  posZr =  pos.z（不變）

Step 1-3 (不變，但使用旋轉後座標): translate → y-rotate → spherical → Φ_x, Φ_y
```
