## T2 Debug 過程

T2 最初設計為：以 `geodetic2cartesian(sat.sublat, sat.sublong, sat.elevation)` 計算衛星 ECEF，再與 `ephem.sat.alt` 比對。

### 第一次失敗（max error = 0.378°）

**原因：`sat.sublat` 是 geocentric latitude，不是 geodetic latitude。**

- PyEphem 的 `sat.sublat` 是衛星位置向量與赤道面的夾角（geocentric），不是測地法線方向（geodetic）。
- 在中緯度（51.9°），兩者差距約 0.19°，傳入 `geodetic2cartesian()` 作為 geodetic lat 使用會造成 ~0.4° 仰角誤差。
- 修正：改用 `_ecef_from_ephem_geocentric(sat)` 直接從 geocentric 球座標計算 ECEF，繞過測地轉換。

```python
# 修正 1（geocentric ECEF）：
r = float(sat.elevation) + _WGS72_A_M   # WGS72 a = 6378135.0 m
x = r * cos(sublat) * cos(sublong)
y = r * cos(sublat) * sin(sublong)
z = r * sin(sublat)
```

### 第二次失敗（residual > 0.01°；check ERAD constant）

**原因：`sat.elevation` 的 ERAD 常數不確定。**

- PyEphem 計算 `sat.elevation = geocentric_distance − ERAD`，但 ERAD 的值可能是 WGS72（6378135 m）、IAU76（6378160 m）或其他。
- 若 ERAD 差 25 m，在 800 km 範圍下造成 ~4×10⁻⁵° 誤差，超過 0.01° 門檻仍不滿足，且無法從外部確認。

### 修正：ENU round-trip（ERAD-independent）

改用 `sat.range`（真實觀測者-衛星距離，無 ERAD 依賴）配合 `sat.alt` / `sat.az` 重建 ENU vector，再透過 `_enu_to_ecef` + `_ecef_to_enu` 還原仰角。

```python
# 從 ephem observer-relative 量測重建衛星 ECEF（不依賴 ERAD）
range_m = float(sat.range)
alt_rad  = float(sat.alt)
az_rad   = float(sat.az)

E_sat = range_m * cos(alt_rad) * sin(az_rad)   # East
N_sat = range_m * cos(alt_rad) * cos(az_rad)   # North
U_sat = range_m * sin(alt_rad)                 # Up

dx, dy, dz = _enu_to_ecef(obs_lat, obs_lon, E_sat, N_sat, U_sat)
sat_ecef_rt = (obs_ecef[0]+dx, obs_ecef[1]+dy, obs_ecef[2]+dz)

E2, N2, U2 = _ecef_to_enu(obs_lat, obs_lon, obs_ecef, sat_ecef_rt)
elev_rt    = _enu_elevation_deg(E2, N2, U2)
# rt_err = |elev_ephem - elev_rt| → 純浮點精度
```

`_enu_to_ecef` 是 `_ecef_to_enu` 的轉置（正交矩陣），R × R^T = I，obs_ecef 在計算中消除。

## 輔助函式設計

```python
# ENU rotation (ECEF delta → ENU)
def _ecef_to_enu(obs_lat, obs_lon, obs_ecef, sat_ecef):
    dx, dy, dz = sat_ecef - obs_ecef
    E = -sin_lon*dx + cos_lon*dy
    N = -sin_lat*cos_lon*dx - sin_lat*sin_lon*dy + cos_lat*dz
    U =  cos_lat*cos_lon*dx + cos_lat*sin_lon*dy + sin_lat*dz

# Inverse rotation (ENU → ECEF delta)
def _enu_to_ecef(obs_lat, obs_lon, E, N, U):
    dx = -sin_lon*E - sin_lat*cos_lon*N + cos_lat*cos_lon*U
    dy =  cos_lon*E - sin_lat*sin_lon*N + cos_lat*sin_lon*U
    dz =              cos_lat          *N + sin_lat          *U
```

## run_sgp4.py 修正

Phase 2 的 C++ ENU frame 設定需要衛星的 **geodetic** 緯度（geodetic lat/lon），但 `sat.sublat` 是 geocentric。

新增 Bowring's iterative method（geocentric ECEF → WGS72 geodetic）：

```python
_WGS72_A_M = 6378135.0
_WGS72_F   = 1.0 / 298.26
_WGS72_E2  = 2 * _WGS72_F - _WGS72_F ** 2   # first eccentricity squared

def _geocentric_to_geodetic(geocentric_lat_deg, alt_above_equatorial_sphere_m):
    phi_c = radians(geocentric_lat_deg)
    r     = alt_above_equatorial_sphere_m + _WGS72_A_M
    p     = r * cos(phi_c)
    z     = r * sin(phi_c)
    lat   = atan2(z, p * (1 - _WGS72_E2))       # initial guess
    for _ in range(6):
        sin_lat = sin(lat)
        v       = _WGS72_A_M / sqrt(1 - _WGS72_E2 * sin_lat**2)
        lat_new = atan2(z + _WGS72_E2 * v * sin_lat, p)
        if abs(lat_new - lat) < 1e-13: lat = lat_new; break
        lat = lat_new
    # compute alt_ellipsoid from p / cos_lat - v
    return degrees(lat), alt_ellipsoid
```

## Key Findings

1. **geocentric vs geodetic**：`sat.sublat` 在中緯度（51.9°）與 geodetic lat 差約 0.19°，傳入 `geodetic2cartesian()` 會造成 ~0.4° 仰角誤差，必須明確轉換。
2. **ERAD 不可靠**：PyEphem 的 `sat.elevation` 基於不確定的 ERAD 常數，任何依賴 `sat.elevation + 某 Earth radius` 的計算都有系統偏差。改用 `sat.range`（真實斜距）可完全規避。
3. **ENU rotation 自洽**：`_ecef_to_enu` 與 `_enu_to_ecef` 是嚴格的互逆矩陣，round-trip 誤差 3.91e-14° 確認 Phase 2 的 ENU frame 計算基礎正確。
